The 5 decisions behind v6

Why text line beats pills · why name went up 25% · why the layout still feels "BookEase"
01

Text line beats pills · less visual weight

Pills draw outlines and fills — five pills = 10 borders + 5 backgrounds competing with photos below. A flat text line has zero chrome. Selected state is a single 2.5px underline + bold weight + dark color. Eye finds the active state in 0.3s without parsing shape.

02

Apple News / iOS Settings pattern

Apple uses this exact pattern for category navigation across iOS, Maps, News, App Store. It's the most Thai-language-friendly because Thai words have different visual widths than English (e.g. "เสริมสวย" 7 chars vs "Salon" 5 chars). Underline scales with word length · pills require padding tweaks per word.

03

Name 12px/700 → 15px/800

25% larger + heavier weight. Was reading as caption ("photo with a label"); now reads as headline ("shop with a face"). Same hierarchy as Airbnb listing cards. Customer's eye lands on photo → name in one saccade instead of two.

04

Distance moved to name row

Top-right of the name row · tabular-num · small 11px/700. Customer can scan distances vertically down the grid without parsing prose. Like Booking.com price column.

05

Photo + name is now ONE unit

Smaller padding between photo bottom edge and name (8px → 10px feels intentional, not awkward). Heavier name weight visually "weights" the card bottom. The card now reads as a single entity, not "photo with text underneath."

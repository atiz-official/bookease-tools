Elon's verdict (do you agree?)

YES · agree. "Apple Pay sheet always fits one screen. If you have to scroll · you've already lost. Stripe Checkout aims for one-screen. Klarna one-screen. Chope one-screen with note."

Math checks out: ~630 px content + ~130 px headroom on 760 viewport. Note input (50 px · 2 lines) fits inline · no collapse needed. Even with iOS keyboard up · CTA stays above keyboard since it's inside scrollable body.

Note is essential per Chope: "ห้องเงียบ · แพ้น้ำมันหอม · มาก่อนเวลา" = real customer needs. Removing it = friction (force user to LINE chat shop separately). Keep inline.

Tradeoffs explicit:

• Always-visible note ≠ collapsed toggle. Trade ~50px viewport for zero discoverability friction.

• Phone-only input ≠ name+email. Customer name comes from auth (BOOK_NOW flow). Email moved post-payment if needed.

• One-line micro-trust ≠ 4-row trust strip. Trust = wordmark + clean layout · not text manifesto.

Recommendation: ship iter5 as Pass 25 v37 React port target. ~90 min · CSS + small JSX. UnifiedPromoInput logic unchanged.

Pass 26 v4 · D1 vs D2 + honest F take

Two implementations of Variant D · plus an answer to "is F your best idea?"

"i like variant F. is it your best idea yet?"

Honest answer: F is the safest idea, not the strongest. F (Pinterest 2-col) is closest to what customers already know (Instagram · Pinterest · current bookease.co · OnlyFans grid). Familiar = low cognitive switching cost. But for trust-purchase decisions where vibe assessment is the limiting factor, F's smaller photos under-deliver vs D's hero card. Each 4:5 photo on F is ~140px wide on phone · D's 16:10 hero is ~340px. F shows 2.5× more shops per scroll but at ⅓ the photo area each.

The right answer is "ship both." F as a power-user "fast browse" toggle button on the home (top-right), D1 as the default. Customer who knows what vibe they want browses in F mode. Customer in undecided/exploratory mode sees the larger D1 cards. Toggle persists in local storage. Like Twitter's "list" vs "expanded" toggle. Same data, two density modes.

Verdict: F = best browse mode · D1 = best decision mode · ship both as toggle

🚀 Ship strategy · ทั้ง D และ F · toggle pattern

Default view = D1 (hotel hero card). New customers + first-time visitors land here. Maximizes vibe assessment per scroll. Card includes 3 inline slots so customer verifies bookability without leaving home.

Toggle to F (2-col grid) via a small icon in the top-right header (next to location pin). Persists in localStorage. Power users + return visitors who already know their preferred shops scan faster in F mode. view=hero|grid URL param so the choice survives shares + links.

D2 is the safer compromise if you ship only one. Keeps the vibe photo but adds 60% more shops per scroll vs D1. Like Booking.com's mobile search-result page (which is exactly this layout). If pilot data shows customers scroll too much in D1, switch default to D2.

Pick one for caravan #1 · D1 if your gut says "premium first impression matters" · D2 if your gut says "Bangkok customers want to see options fast." Both ship the same filter system (category row + time/location row). Same backend contract. Same card data. Only the visual presentation differs.
